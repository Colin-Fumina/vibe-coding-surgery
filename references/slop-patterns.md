# AI 病灶图鉴：十种形状

> 这不是"代码坏味道"大全，只收 **AI 反复迭代特有的**那些。
> 每条写：AI 为什么这么写 / 长什么样 / 怎么判 / 修法 / 别误判。

---

## 0. 为什么单列一份

人写屎山靠"赶工期 + 没人管"，AI 写屎山靠"**没有跨会话记忆 + 每轮只求当前报错消失**"。

所以它的病灶有**固定形状**：重复、补丁、抽象过早、证据造假。
形状固定就意味着可预测——这张表就是预测清单。

**核心区分**：人的屎山是"欠账"，AI 的屎山是"**每一轮都以为自己在做对的事**"。
所以修的时候不能只删代码，要同时掐掉产生它的条件（见 §12 约束文件族）。

## 1. 十种形状

### P1 并行双胞胎（Duplicate Twins）

| | |
|---|---|
| **AI 为什么** | 上一轮写过这个函数，这一轮上下文里没有 → 换个名字再写一遍。或 A 改了，B 的同一逻辑没跟着改 |
| **长什么样** | 函数体逐字相同、只差变量名；两个组件做同一件事；两个 store 存同一份数据 |
| **怎么判** | F4 近名扫描 → F5 相邻读 → 逐行比对（不许只看名字） |
| **修法** | 合（先做 §10.2 等价验证） |
| **别误判** | 方向相反的（正数天 / 负数天）、精度不同的（展示 / 计算）可能是真的两个 |

### P2 补丁摞补丁（Patch Stacking）

| | |
|---|---|
| **AI 为什么** | 不敢改原有逻辑，只敢在外面再包一层 `if`。每轮加一层，五轮之后没人看得懂 |
| **长什么样** | 一个函数 5–8 层嵌套；每层都带一句"如果是 X 就…"；早 return 与 if 混用；同一变量反复判空 |
| **怎么判** | 嵌套深度 >4；同一函数里对同一对象判空 ≥3 次 |
| **修法** | 压平（守卫提前 return）→ 仍读不懂就重写 |
| **别误判** | 权限校验、降级策略天然多层——看每层职责是否有归属（§9.2 压平前置） |

### P3 过早抽象（Premature Abstraction）

| | |
|---|---|
| **AI 为什么** | "为了可扩展性"；或上一轮抽了接口，这一轮又加一层工厂 |
| **长什么样** | 1 接口 + 1 实现 + 1 工厂 + 1 注册表；`BaseXxx` 只有一个子类；改一个行为要动 4 个文件 |
| **怎么判** | 抽象的实现数 = 1；新增一个同类功能要写 5 个文件 |
| **修法** | 删（把实现拉回调用点），等第二个实现出现再抽 |
| **别误判** | 测试替身需要接口；插件点即使只有一个实现也是设计意图 |

### P4 幻觉依赖（Hallucinated Dependency）

| | |
|---|---|
| **AI 为什么** | 编一个"应该有"的包名，或记得某个 API 存在但其实没有 |
| **长什么样** | `npm view` 查不到；装了但 0 引用；import 了不存在的导出；lockfile 里根本没有 |
| **怎么判** | `commands.md` §3 |
| **修法** | 删；需要功能就找真实替代（先确认它真的存在） |
| **别误判** | 私有包 / workspace 内部包查不到是正常的 |

### P5 吞错误（Error Swallowing）

| | |
|---|---|
| **AI 为什么** | 测试红了、或运行时崩了，catch 住就"通过"了。这是它最省力的绿 |
| **长什么样** | `catch {}`；`catch (e) { console.log(e) }`；`catch { return [] }`；`?? []` 遮住数据缺失 |
| **怎么判** | 每个 catch 都要能回答："这里失败后，调用方怎么知道？" 答不出就是吞 |
| **修法** | 抛 / 记结构化日志 / 明确降级并在旁边注释为什么 |
| **别误判** | 读配置文件时 `JSON.parse` 配默认值合理——看有没有注释和边界说明 |

### P6 假测试（Fake Tests）

| | |
|---|---|
| **AI 为什么** | 为了"有测试"而写测试，或为了覆盖率好看。它知道名字比断言便宜 |
| **长什么样** | 测试名承诺错误路径但没断言；只测 happy path；mock 比断言多；唯一断言是 `toBeDefined()` |
| **怎么判** | F11 测试名-断言对照；§10.3 破坏抽检（改坏三处看红不红） |
| **修法** | 补断言；补不了就删——**假测试比没测试更坏**，它会让后面每个 AI 以为有安全网 |
| **别误判** | 冒烟测试只验"能跑通"是有意的，标清楚就行 |

### P7 文档-代码分叉（Doc Drift）

| | |
|---|---|
| **AI 为什么** | 文档是上一轮写的，代码是这一轮改的，没人回头改文档。**文档骗 AI 比骗人严重**——人会怀疑，AI 会照做 |
| **长什么样** | 文档里的命令不存在；说的库没装；说的功能没实现；同一版本号三个副本全不一样 |
| **怎么判** | F2 单一事实源对账 + F3 文档-事实交叉 |
| **修法** | 改文档（以代码为准）；删掉无法验证的承诺 |
| **别误判** | 写"计划中"的功能不算分叉——但必须显式标"未实现" |

### P8 状态蔓延（State Creep）

| | |
|---|---|
| **AI 为什么** | 每加一个功能就加一个 state，不同步就加 `useEffect` |
| **长什么样** | 派生数据被另存；effect 里 set 别的 store；单组件 5 个 `useEffect`；依赖数组 6 项 |
| **怎么判** | `commands.md` §4 三条判据 |
| **修法** | 收成单向数据流；**能算出来的不存** |
| **别误判** | 真正的外部同步（订阅、定时器、DOM 事件）需要 effect |

### P9 巨型文件（God File）

| | |
|---|---|
| **AI 为什么** | 每次都往同一个文件追加，因为"相关"；没人负责拆 |
| **长什么样** | 2000 行单文件，7 种职责；或 500 行的万能 `utils.ts` / `store.ts` |
| **怎么判** | §7.2 第 2 步：它该属于哪？和邻居是一类吗？ |
| **修法** | 按**意图步骤**拆，不按行数拆（§9.2） |
| **别误判** | 大但职责单一（代码生成器、schema 定义、路由表）是正常的 |

### P10 类型逃生（Type Escape）

| | |
|---|---|
| **AI 为什么** | 类型报错时用 `any` 压下去，比修数据形状便宜 |
| **长什么样** | `any` 密度排行前几；`as unknown as T`；`@ts-ignore`；可选链深度 >3 |
| **怎么判** | `commands.md` §1；`?.a?.b?.c?.d` 出现即可疑 |
| **修法** | 修**数据形状**（在边界做一次校验），不是修类型 |
| **别误判** | 第三方库类型缺失时的局部 cast 有理由——看它有没有收在一个 adapter 里 |

## 2. 怎么用这张表

1. 扫描时每发现一条，**先归类到 P1–P10**。
2. **归不了类的，可能不是屎山**——是真业务复杂度。回 §7.4 重新判。
3. 同一类出现 ≥3 次，按下面 §3 处理。

## 3. 一个反直觉的判据（重要）

> **同一个病灶出现 3 次 = 流程问题，不是代码问题。**

逐个修只会让它换个地方长回来——因为你没改变"AI 下一轮还会这么写"的条件。

这时候正确顺序是：

```
先加约束（§12 / templates.md）
  → AGENTS.md 红线 / TASK.md 合同 / 可选 hook
  → 再回来修
```

**这也是这份 skill 必须带 §12 的原因**：只修代码的审查者，是给漏水的水管换拖把。

---

## 4. 三种"看起来像屎山但不是"

| 现象 | 为什么不是 | 判据 |
|---|---|---|
| 分支多、case 多 | 业务本身就有这么多情况 | 每个分支能对应一条可陈述的规则 |
| 文件大 | 单一职责 + 线性结构 | 从上往下读不用跳来跳去 |
| 有注释掉的代码 | 短期保留待确认 | 有标注日期和原因，且 ≤2 处 |

**别把"我不熟这个领域"当成"这是屎山"。** 判据不够时，标"推测"，别下结论。
