# 约束文件族（模板）

> 原则：**能被工具强制的，就不写进文档。**
> 文档只写工具管不了的东西：边界、职责、不许做什么、为什么。

---

## 1. 七个文件各管一件事

| 文件 | 管什么 | 长度上限 |
|---|---|---|
| `AGENTS.md`（根） | 硬规矩 + 去哪找细节 | **<200 行 / <2000 token** |
| `<模块>/AGENTS.md` | 职责、不管什么、能依赖谁 | 8–15 行 |
| `CONTEXT.md` | 术语表：一个概念一个名字 | 随项目长 |
| `docs/adr/NNNN-*.md` | 为什么这样设计 | 一页一个 |
| `docs/FINDINGS.md` | 已知病灶 + 为什么还没修 | 随项目长 |
| `docs/PLAN-<日期>.md` | 本轮要改的片 + 顺序 + 回滚 | 一轮一份 |
| `TASK.md` | 本次任务的合同 | 半页 |

**目录形状**：

```
my-project/
├── AGENTS.md
├── CONTEXT.md
├── TASK.md
├── docs/
│   ├── FINDINGS.md
│   ├── PLAN-20261109.md
│   └── adr/0001-*.md
└── src/<subsystem>/AGENTS.md
```

## 2. 写法七条（决定 AI 会不会真听）

| 原则 | 错 | 对 |
|---|---|---|
| **用禁止句** | "应该先看看路由表" | "不许在没对照路由表的情况下开工" |
| **后果写同句** | "写代码前加载规则" | "不许在加载规则前写代码——你对这工具的通识在这个仓库是错的" |
| **给可执行步骤** | "确保文档最新" | "跑 `git diff HEAD~1 --name-only`，逐份更新；输出为空就停" |
| **规则旁放反例** | 只写规则 | 每条下面跟 Bad/Good |
| **硬门禁 + 触发条件** | "考虑要不要写 ADR" | "改任何公开 API、加依赖之前，先读 `docs/adr/` 索引" |
| **一处写处处链** | 复制三份 | 写一次，别处链接（复制会漂移） |
| **限定到动作** | "遵循最佳实践" | "不要重写已经正确的段落，只改受本次改动影响的行" |

**一句话**：建议式写法（"应该""考虑""尽量"）会让 AI 跳过规则去猜。禁止式写法测起来明显更好。

## 3. 根 `AGENTS.md` 模板

```markdown
# 这个仓库的硬规矩

## 绝对红线（违反则整片回滚）
- 严禁在没跑通既有测试的情况下改核心计算/数据转换逻辑
- 严禁在同一提交里混「结构调整」与「行为变更」
- 严禁为了修类型错误而用 any / @ts-ignore / as unknown as T
- 严禁空 catch；异常必须记日志、向外抛、或走专用降级策略
- 严禁顺带改动：格式化别的函数、改名、加无关日志

## 动工前必做三步
1. 读 CONTEXT.md 确认术语
2. 读 <目标目录>/AGENTS.md 确认边界
3. 在 TASK.md 写清「目标 / 改哪些文件 / 不做什么 / 怎么验」
   —— 获得确认后才动手

## 提交信息
- 结构改动以 `[surgery]` 开头，行为改动以 `[behavior]` 开头
- 两者不许混在一条里

## 去哪找
术语 CONTEXT.md · 设计理由 docs/adr/ · 已知问题 docs/FINDINGS.md
```

## 5. `TASK.md` 模板（每次让 AI 干活前贴这半页）

```markdown
## 目标
（一句话，可验证）

## 范围
只改：
可以连带：

## 不做
不动数据库；不改界面文案；不顺手改名；不加依赖

## 怎么算做完
1. 现有测试全绿
2. 手动验证：<具体步骤>
3. 提交以 [surgery] 开头，diff 里没有格式化噪音
```

## 6. 其余四个（照格式类推）

```markdown
# CONTEXT.md
## 术语
- Task（不是 Todo / Item / Entry）：用户要做的一件事，有 id、标题、状态、时间窗
- Entry：只在数据层出现，指任务在数据库里的一行

# docs/FINDINGS.md
## N2 store.ts 状态重复
- 现象：taskStore 与 todoStore 各存一份，靠 useEffect 同步
- 影响：改一处另一处可能不同步
- 为什么还没修：同步代码里有 3 条没写下来的业务规则
- 什么条件下能修：确认这 3 条规则的归属之后

# docs/adr/0003-single-store.md
## 决策
所有任务状态只放 taskStore。
## 原因
两个 store 同步过一次数据丢失，且没有测试能发现。
## 后果
读写都要经过 taskStore；todoStore 只能做派生视图。
```

## 7. 文档规则与实际冲突时

**优先级：实际产物 / 实际状态 > 声明文件 > 文档。**

冲突时**改文档，不改事实**。

若规则本身不适用当前场景（例如"每次改动升版本"用在快照演练上），标为**「规则豁免」并记录理由**——不要为了守规则而制造一个不存在的版本号。

## 8. 机械化门禁（可选，推荐）

规则写在文档里靠自觉，装成 hook 才靠得住。

```bash
# .git/hooks/commit-msg —— 强制标签
grep -qE '^\[(surgery|behavior)\]' "$1" || {
  echo "提交信息必须以 [surgery] 或 [behavior] 开头"; exit 1; }
```

```bash
# .git/hooks/pre-commit —— 单片上限 + diff 纯度
changed=$(git diff --cached --numstat | awk '{a+=$1;d+=$2} END{print a+d}')
[ "$changed" -gt 300 ] && { echo "本次改动 $changed 行，超过 300 行上限，请拆片"; exit 1; }
git diff --cached | grep -E "^-\s*(expect|assert)" && { echo "禁止删除断言"; exit 1; }
git diff --cached | grep -E "^\+.*(\bany\b|@ts-ignore)" && { echo "禁止新增类型逃生符"; exit 1; }
exit 0
```

```bash
chmod +x .git/hooks/commit-msg .git/hooks/pre-commit
```

**装 hook 属于改变仓库，必须先问。** 装了之后 AI 就没法"悄悄"违规。

---

## 9. 防腐化三条

1. 每条规则带一句"为什么"，没理由的规则第一个被删
2. 根 `AGENTS.md` 不许超 200 行——超了就是文档在替工具干活
3. 每次修完最多新增**一条**规则，且必须能被工具或流程验证

**规则也会变成屎山。** 加规则的成本不是写它的时间，是以后每次都要读它。
